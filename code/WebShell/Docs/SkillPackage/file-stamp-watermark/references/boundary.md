# 软件功能边界与错误处理（boundary）

> 本文件是判断"需求是否超出软件能力"与"任务出错如何应对"的依据。**第 1 层定位、第 2 层精确规则就是最终执行口径，智能体不可发明新规则。**

## 一、软件功能边界（自定义任务时判断需求的关键依据）

### 第 1 层 · 软件定位

文件批量盖章与水印工具 = "PDF 盖章 + 文字水印"批量处理工具，通过命令行 JSON 调用。只做这两类操作，**不做**：PDF 内容编辑、图片处理（除文字水印）、格式转换、文档生成。

### 第 2 层 · 4 类任务的精确规则

- 盖章：范围（全部 / 首页 / 尾页 / 自定义页码）、位置（居中 / 百分比）、骑缝章（类型：全部页 / 奇数页 / 偶数页；位置：上 / 下 / 左 / 右、位置百分比、自动分割）、随机角度位移、盖章渲染——参数含义与默认值见 task-spec.md；
- **按文字盖章 = 写死规范**：按用户指定文字**精确搜索匹配**定位盖章，智能体**不可自行改变匹配逻辑**（如改成模糊匹配）；
- 水印：文字支持多行换行；字号按 `fsToS`（页面短边比例，**必须保留该字段**）；透明度/旋转默认值见 task-spec.md；
- 批处理：只扫各文件夹**根目录**（不看子目录）；`input` **仅支持文件夹目录**（单路径或数组，不支持单文件路径）；输出**永不覆盖源文件**，默认各源文件夹内 `已处理/`；需要按文件粒度处理（部分文件跳过）时，用临时文件夹方案（见 task-spec.md §五）。

### 第 3 层 · 软件做不到的（识别后变通，不硬跑）

| 用户需求 | 软件现实 | 智能体的处理 |
|---|---|---|
| "哪里该盖章、哪里不该盖章"（语义判断） | 只认 全部 / 首页 / 尾页 / 自定义 / 按文字 | **预设流程（1/2/3）**：拆成规则组合 + 建议，让用户确认；**对话定制（4）**：智能体可读取文件内容判断哪里该盖/不该盖，翻译成按文字盖章 + 关键词/偏移等可执行规则 |
| "盖在落款处/签字处"（智能定位） | 只认 居中 / 百分比 / 偏移 | 用「按文字盖章」（落款单位名）+ 偏移；文字不存在则建议尾页盖章 |
| 逐页不同章 / 不同位置 | 一次任务统一规则 | 拆成多个任务（每段页范围一个），或统一位置，让用户选 |
| 图片上盖图章 | **不支持**（图片只支持文字水印） | 明确告知做不到 |
| 合并 / 拆分 / 压缩 / 转格式 | 不支持 | 明确告知，不绕弯 |

### 第 4 层 · 智能体职责边界

- **能**：理解需求、提出建议、把需求翻译成软件规则、组合 / 拆解任务、默认值兜底、写 JSON、执行、如实反馈；**对话定制（4）模式下读取文件内容做语义判断**（哪里该盖/不该盖、选关键词）并翻译成软件可执行规则；
- **不许**：改写死规则、让软件跑超出能力清单的操作、跳过用户确认、虚构成功结果、**压缩公章尺寸（铁律）**——章尺寸不可压缩时，用位置偏移（offset）等参数调整实现效果。

### 第 5 层 · 信息收集清单（自定义模式下问哪些）

- **必问**：需求描述、源文件目录（可多个）、处理对象（PDF / 图片 / 混合）、期望效果；
- **按需问**：印章 / 水印具体参数、特殊约束（页范围 / 位置 / 骑缝章等）、输出要求；
- **兜底**：用户说不清 → 用默认值并向用户说明，不满意再调。

### 第 6 层 · 需求翻译示例（自然语言 → 规则组合的参照）

- 示例 1："只在合同落款单位处盖章" → 「按文字盖章」（落款单位名，如"西安某某公司"）+ 位置偏移；该文字在 PDF 中不存在 → 说明情况，建议改「尾页盖章」；
- 示例 2："每页不同位置盖章" → 一次任务做不到 → 拆成多个任务（每段页范围一个位置），或统一位置，让用户选；
- 示例 3："水印每页顶部和底部各一行" → 软件单框水印做不到 → 建议：一个框内多行文字（放中上部），或只做一个位置，让用户选；
- 示例 4："在合同落款处盖公章" → 关键词**不一定等于用户口头说的公司名**——合同正文里公司名常出现多次，直接用它做关键词会在所有位置盖章。应结合文档内容选能**唯一定位**的关键词（如「公司名（盖章）」仅命中签署页），并在方案中向用户说明。

## 二、示范项目（可复用样例）

### 示范 1：按文字盖章——关键词要能唯一定位（避免全文多处命中乱盖）

- **需求**：给合同签署页甲方盖章处盖公章。
- **难点**：合同正文里公司名出现多次，直接用公司名做关键词会在所有命中处盖章（乱盖）。
- **做法**：
  1. 读取 PDF 文本，找出「公司名（盖章）」这种**签署页专属**写法——全文仅命中签署页 1 处；
  2. 用 `pdf-text-stamp` 任务，`textStamp.keyword` = 「公司名（盖章）」，`matchMode` 保持 `all`（此时全文仅 1 处，安全）；
  3. 执行后如实反馈，并在方案中向用户说明关键词选取理由。
- **要点**：关键词不等于用户口头说的公司名；先读内容确认唯一性，再执行。

### 示范 2：章必须压甲方名、不压乙方名——几何约束 + 移动章中心（对话定制任务）

- **需求**：合同签署页盖公章，**必须压住甲方公司名，绝不能压到乙方公司名**；公章尺寸不可压缩（铁律）。
- **难点**：签署页甲方、乙方两行文字垂直间距仅 **16.5mm**，而公章直径 **44mm**——按默认落章（章中心=文字中心）必然同时压到乙方。
- **做法**：
  1. **读取内容 + 测量**：定位签署页两行文字坐标（PDF 坐标），甲方行 y≈681、乙方行 y≈634（间距 46.8pt≈16.5mm），章半径 62.4pt；
  2. **识别几何约束**：章直径 > 两行间距 → 默认落章位置不可行；
  3. **铁律不缩章**：不缩小公章（44mm），改用 **offset 移动章中心**——章中心对准甲方名称（左移 6.3mm），并上移到章下缘高于乙方文字上沿（上移 8.8mm），留约 1mm 安全余量；
  4. **执行**：`pdf-text-stamp` 任务，关键词用「公司名（盖章）」（仅签署页 1 处），`textStamp.offset = {"x": -6.3, "y": -8.8}`，**不填 `sizeMm`**（保持 44mm）；
  5. **闭环验证**：输出后解析章图绘制位置/渲染页面像素，确认章中心实测位置、章直径未变（≈44mm）、章覆盖甲方名称 ≥ 一半、乙方上方有余量——不符则微调 offset 重跑，验证通过才交付。
- **要点**：布局几何限制优先于"默认落章位置"；尺寸不可改时，位置偏移（offset）是正确出路；**每次输出都要验证位置再交付**。

## 三、常见错误处理

| 现象（日志内容） | 含义 | 处理 |
|---|---|---|
| `任务文件不存在` | JSON 路径写错 | 检查 JSON 路径 |
| `任务 JSON 解析失败` | JSON 格式错误 | 检查引号/逗号/编码（必须 UTF-8） |
| `缺少 task 或 input` | 字段缺失 | 补全 `task`/`input` |
| `输入目录不存在` | 源文件夹路径错误 | 向用户核实路径 |
| `印章图片不存在` | 印章路径错误 | 向用户核实印章路径 |
| `缺少 watermark.text` | 水印任务缺文字 | 向用户要水印文字 |
| `批处理超时` | 文件过多处理超 10 分钟 | 告知用户分批处理 |
| `加密或无法打开` | 个别 PDF 加密/损坏 | 报告该文件，其余已处理 |
| 文件夹里没有 PDF 或图片 | 智能体识别源文件夹无支持文件 | 提示用户该文件夹没有可处理的文件，并提醒检查是否给成了「已处理」等输出目录/空文件夹，请提供正确的源文件夹 |
| 退出码 2 | 部分失败 | 读日志 `[失败]` 行，向用户说明 |

## 四、自检要点（开始任务前）

1. 本次需要盖章 → 印章库有印章图片（软件默认不携带印章，需用户导入）；并运行 `seal_info.py` 读取 config.ini 全部参数（每章尺寸/不透明度/旋转/渲染 + 全局配置），带入会话备用；
2. 手册/模板齐全（`运行组件\智能体调用\` 存在）→ 不存在说明用户未运行过 EXE，先让用户运行一次；
3. **`运行组件\config.ini` 只能读、绝不能改（铁律）**：读取必须经 `seal_info.py`（EXE --stamp-info 转 UTF-8），禁止直接打开（GBK 乱码）、禁止修改——软件配置由软件界面维护。

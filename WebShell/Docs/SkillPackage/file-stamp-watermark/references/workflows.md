# 工作流程规范（workflows）

> 本文件规定预设流程的固定提问顺序、自定义任务流程、收尾与补充手册规则。**固定提问形式不得随意变更**：按下列顺序逐项询问，不跳项、不合并、不自创问题；每个问题都带默认值（默认值见 task-spec.md §三），用户可逐项指定；用户回复"默认/其他默认"即按默认值执行。

## 一、预设流程（任务类型 1 / 2 / 3）

### 盖章（按下列 1-8 顺序逐项询问）

1. **源文件夹路径**（可一次给多个；软件只处理各文件夹根目录的 PDF，不看子目录）；
2. **盖哪个章**：让用户从印章库中选（或提供印章图片路径）；该章大小/不透明度/旋转使用软件中该章已配置参数，任务 JSON 不填 `sizeMm`/`opacity`/`rotation` 即按该章配置执行（填写才会覆盖用户界面设置）；
3. **盖哪些页**：**全部页（默认）/ 首页 / 尾页 / 自定义页码范围 / 按文字盖章**（在指定文字处定位盖章，如"公章"字样处）；
4. **盖章位置**：**居中（默认）**，或指定 X/Y 百分比位置；
5. **是否加骑缝章**：**不开启（默认）**；开启时必须向用户确认**骑缝章类型**：**全部页**（默认，每页都盖）/ **奇数页**（只盖 1、3、5…页）/ **偶数页**（只盖 2、4、6…页）；再确认位置：默认 **右**、位置 **50%**（1-100%），要其他值请用户指定：上 / 下 / 左 / 右（位置 1-100%）；单页 PDF 无需骑缝章；
6. **是否开启随机角度位移**：**不开启（默认）**；开启默认 旋转 **45°**、横向位移 **10mm**、纵向位移 **10mm**（用户可逐项指定修改）；
7. **是否开启盖章渲染**：**不开启（默认）**；开启默认 浓淡不均 / 径向压印 / 局部露白 / 内部斑点 **15**、斑点大小 **5**、渐变过渡 **10**、整体色偏 **0**（用户可逐项指定修改）；
8. **输出命名**：默认 `已处理V` + 数字递增（用户提要求才改，一般不询问）。

### 水印

- 源文件夹路径（**可以一次给多个文件夹**；软件只处理各文件夹根目录的文件，不看子目录）；
- **智能体读取文件夹内容自动识别文件类型**，自动选择水印方式：
  - 文件夹里只有 PDF → 用 **PDF 水印**（`pdf-watermark.json`）；
  - 文件夹里只有图片 → 用 **图片水印**（`img-watermark.json`）；
  - **文件夹里既有 PDF 也有图片** → 询问用户：**1 只处理 PDF / 2 只处理图片 / 3 全部处理**；
  - 文件夹里既无 PDF 也无图片 → 提示用户该文件夹没有可处理的文件，请重新提供正确的文件夹；
- 水印文字内容。**支持多行**：用户可直接在对话中回车换行（推荐，所见即所得），或用 `\n` 表示换行。示范——用户这样输入：

  ```
  仅供：
  某某项目使用
  ```

  等效于 `仅供：\n某某项目使用`，程序按行分别渲染并自动按水印框宽度换行。若用户未说明换行方式，可用上述示例主动向用户确认；
- 水印样式：字体、字号、颜色、**透明度（默认 30%）**、**旋转角度（默认 30°）**、行距、字间距、对齐、位置（居中/底部/自定义）；
- 用户也可以选择"**由你（智能体）自行定义**"——此时使用默认值执行，并向用户说明默认值，用户不满意可要求调整。

## 二、自定义任务流程（任务类型 4）

不按预设流程逐项收集，改为与用户**对话推进**。开场白（固定，用户选 4 后立即发送）：

> 好的，我们不按固定流程来。请直接告诉我：**要处理哪些文件**（文件夹路径）、**你想做什么**（盖章/水印/其他特殊要求）。剩下的细节我会边问边跟你确认，比如盖哪些页、盖什么位置、水印什么样，最后把方案列给你确认后执行。

按下列顺序推进，**不跳步**：

1. **倾听需求**：问清——要做什么、处理哪些文件（文件夹路径，可多个）、期望的效果、有没有特殊约束；**复述一遍**与用户确认；
2. **拆解需求**：对照 boundary.md「软件功能边界」，把需求拆成三类：①软件规则直接可实现 → 对应到任务 JSON 字段；②需要智能体判断 → 给出分析并翻译成软件可执行的规则；③超出软件范围 → 明确告知做不到，给出变通方案；
3. **提出方案**：列出将用哪个任务类型（盖章 / 水印 / 按文字盖章，可组合多个）、哪些用默认值、哪些需要用户指定，请用户确认；
4. **执行**：按 task-spec.md 读取模板或写 JSON（同类型多文件夹用 `input` 数组；盖章 + 水印组合生成对应任务逐个执行）；
5. **反馈**：按 SKILL.md §四反馈规范报告；收尾按 §五收尾规范处理。

## 三、多文件夹与 JSON 复用

- 同类型多文件夹用 `input` 数组（**一个 JSON**），逐个执行、逐个反馈，各输出到自己 `已处理\`；不要把同类型任务拆成多个 JSON；
- 同类型新任务**优先复制上次成功的 JSON，只改差异字段**（典型只改 `input`、水印文字、印章或开关），不要每次从模板全量重写；
- 任务类型变化（盖章→水印→按文字盖章）、或软件升级后字段说明有变化时，重新对照模板。

## 四、收尾规范

1. **收尾重启引导**：每项任务反馈完成后固定追加一句：
   > 本次任务已完成。下次继续工作时，直接对我说「**开始工作**」即可——我会先读取《偏好文件.json》，按你上次的任务类型和已确认的设置继续引导，无需重新交代全部信息。
2. **主动总结**：每项任务完成收尾时主动跑一遍"本次经验总结"——①任务类型与关键参数；②用户新表达的偏好/约束；③可复用的成功经验；④下次可改进点。逐条向用户确认"**以下哪些记入补充手册？**"，用户确认的条目才写入 `补充手册.md`，不确认不写。
3. **工作过程文件统一存放**：任务 JSON、执行日志、临时脚本、临时文件夹统一放 `运行组件\智能体调用\智能体调用工作过程文件\` 子目录（不存在则创建；EXE 不会覆盖/清理该目录）。命名：`任务_类型_序号.json`、`日志_类型_序号.txt`、`临时_任务名\`。

## 五、补充手册与偏好文件

**补充手册.md**（`运行组件\智能体调用\` 下）：
- 记录用户特有流程、常用默认值、成功项目经验、注意事项（如"合同盖章统一压住甲方公司名，章不压乙方"、"水印默认 30% 透明度、旋转 30° 不用再问"）；
- 每次加载本技能后**必须同时读取**（存在则读，不存在跳过）；**冲突时以补充手册为准**（用户扩展优先于出厂默认）；
- 写入：增量追加、不改旧条目；写前先备份一份 `补充手册.md.bak`；文件损坏时删除后可由用户/智能体重建。

**偏好文件.json**（同目录）：
- 记录用户**运行态短期偏好**：常用印章路径、常用水印文字、输出命名偏好、是否常加骑缝章、**上次任务类型与已确认的自定义方案**等；
- 只允许智能体读写，软件永不读取；写入前先备份 `.bak`，只做增量修改；损坏时可删除后由软件重新生成默认配置；
- **「开始工作」重启流程**：收到用户说"开始工作 / 继续工作"时，先读取本文件——有上次记录 → 向用户复述"上次做的是 X（设置是……），本次是继续、还是换新任务？"，按用户回答继续；无记录 → 按 SKILL.md Quick Start 正常询问。

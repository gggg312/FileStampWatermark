# 文件批量盖章与水印工具（File Stamp Watermark）

**技能包版本：{{VERSION}}**（必须与软件 EXE 版本一致。加载技能包前请运行软件 EXE `--version` 核对；不一致说明技能包为旧版，按《智能体调用手册.md》「一点五」工作方式选择流程处理。）

## 一、技能定位

本技能让智能体通过**本地 EXE 命令行接口**完成三类批处理任务，全程无需用户手动操作软件界面：

| 任务 | 说明 |
|---|---|
| PDF 盖章 | 给文件夹内全部 PDF 盖章（全部页/首页/尾页/自定义范围/按文字盖章），可加骑缝章、随机角度位移、盖章渲染 |
| PDF 文字水印 | 给文件夹内全部 PDF 加文字水印（支持多行、横竖页字号一致） |
| 图片文字水印 | 给图片文件夹内全部图片加文字水印 |

**架构**：本技能 = 遥控器（知识+脚本）；软件 EXE = 执行器。技能只负责定位 EXE、生成/复用任务 JSON、调用 `--batch`、解析结果并反馈；所有 PDF/图片处理由 EXE 完成。

**跨平台铁律**（必须遵守）：
1. 执行只用 EXE 的 CLI（`--batch`/`--version`/`--log`），不调用任何平台私有工具或 API；
2. 脚本只用 Python 标准库（`subprocess`/`json`/`os`），零第三方依赖；
3. 本技能文档不掺平台私货，任何智能体按本文即可完整执行。

## 二、Quick Start（每次任务的固定流程）

按以下顺序执行，**不跳步、不合并、不自创问题**：

1. **定位软件文件夹与 EXE**：先确认用户是否把软件文件夹放进了工作区。用 `scripts/find_exe.py` 定位主程序（根目录唯一 exe + `--version` 验证 + 版本最大者优先）。找不到运行组件目录/EXE 时，提醒用户：**先双击运行一次软件 EXE（窗口正常显示后关闭）**，软件会自动生成 `运行组件\`（含印章库、任务模板），再继续。
2. **自检**（仅首次加载执行一次）：
   - 本次需要盖章 → 检查 `运行组件\印章库\` 是否有印章图片（.png/.jpg）；**软件默认不携带任何印章**，没有则让用户在软件「印章参数 → 选择印章」中导入自己的公章后关闭软件，再继续；同时**运行 `scripts/seal_info.py` 读取 config.ini 全部参数**（每章已保存的尺寸/不透明度/旋转/去白/渲染 + 全局配置），把参数带入会话备用，用户调整参数时直接对照引用；
   - 只做水印任务 → 跳过印章检查（也可运行 seal_info.py 读取全局配置备用）；
   - **`运行组件\config.ini` 只能读、绝不能改（铁律）**：必须经 `scripts/seal_info.py`（内部走 EXE --stamp-info 转 UTF-8）读取，禁止直接打开文件（GBK 会乱码），禁止修改——软件配置由软件界面维护。
3. **询问任务类型**（可多选，用户直接回编号或语言描述均可）：
   - **1 盖章** / **2 水印** / **3 盖章 + 水印**（=1+2，盖章先执行、水印后执行）/ **4 对话定制任务**（不按预设流程，与用户对话推进，见 references/workflows.md §自定义任务流程）
4. **按任务类型收集信息**：固定提问顺序见 references/workflows.md；每个问题都带默认值（默认值见 references/task-spec.md §默认值总表），用户回复"默认"即按默认值执行。
5. **确认后执行**：把收集到的信息完整复述给用户确认（任务类型、全部源文件夹、印章/水印参数、骑缝章等）→ 用户确认后按「三、执行方式」生成/复用任务 JSON 并调用。
6. **按「五、结果反馈」报告**，收尾按「六、收尾规范」处理。

> 详细工作流、自定义任务流程、提问顺序：**读 `references/workflows.md`**；任务字段含义与默认值：**读 `references/task-spec.md`**；软件能力边界与错误处理：**读 `references/boundary.md`**。

## 三、执行方式（scripts）

### 1. 定位主程序

```bash
python scripts/find_exe.py "<软件文件夹路径>"
```

- 返回主程序绝对路径（`--version` 输出含 `文件批量盖章与水印工具` 且版本最大者）；
- 输出 `NOT_FOUND` 时按 Quick Start 第 1 步处理（提醒用户先运行一次 EXE）。

### 2. 列出可用印章

```bash
python scripts/list_seals.py "<软件文件夹路径>"
```

- 返回 `运行组件\印章库\` 下印章文件名列表；空列表 = 未导入印章（盖章任务前必须解决）。

### 2.5 读取印章与配置参数

```bash
python scripts/seal_info.py "<软件文件夹路径>"
```

- 返回 UTF-8 JSON：`tool`/`version`；`config` = config.ini 全部节与键值（原样）；`seals[]` = 印章清单（`name`/`path` + `params`：sizeMm/rotation/rotationHandle/opacity/randomParams/randomRange/randomOffsetXMm/randomOffsetYMm/removeWhite/tolerance/maxSplit/textureQuality/textureBrightness/textureBlob/textureGradient/textureWhite/textureSpot/textureRadial/textureCast/texturePresetIndex）；
- 盖章/按文字盖章任务**自检时必须调用一次**，把 `seals` 参数带进会话；用户说"章大一点/小一点/透明一点"或指定数值时对照已读参数确认（对应 JSON 字段填覆盖值，不填则按该章已保存值执行）；
- 只读不改 config.ini（铁律）。

### 3. 执行任务

```bash
python scripts/run_task.py "<软件文件夹路径>" "<任务.json路径>" "[日志路径]"
```

- 脚本内部执行：`"<EXE>" --batch "<任务.json>" --log "<日志路径>"`，解析退出码与日志；
- 日志路径缺省写 `运行组件\智能体调用\智能体调用工作过程文件\日志_任务_序号.txt`；
- 任务 JSON 统一放 `运行组件\智能体调用\智能体调用工作过程文件\`（不存在则创建），不要散落在软件根目录。

### 4. 任务 JSON 规范

- **模板**：`assets/` 下有 4 个官方模板（pdf-stamp / pdf-watermark / pdf-text-stamp / img-watermark），**从模板出发，不要从零写 JSON**；
- **必须修改的字段**：`input`（源文件夹，可单个路径或数组=同类型一次处理多文件夹）、盖章任务 `stamp.image`、水印任务 `watermark.text`、按文字盖章 `textStamp.keyword`——不改会出错或输出不符合要求（详见 assets 内 `_说明`）；
- **JSON 复用工作流**：首次任务 → 读模板填参 → 另存为新 JSON → 执行成功保留；后续同类型任务 → **优先复制上次成功的 JSON，只改差异字段**（典型只改 input），不要每次全量重写；任务类型变化时回到模板；
- 替换后**另存为新文件**，绝不覆盖模板本身；顶层 `_说明` 字段软件自动忽略。

## 四、结果反馈

1. **退出码**：0 = 全部成功；1 = 参数/路径错误（任务未执行）；2 = 部分文件失败（明细见日志）。
2. **日志**：命令 `--log` 指定路径；日志末尾 `===== 给用户的反馈 =====` 段落可直接向用户转述。
3. **反馈必须包含**：每个输出文件的实际文件名（含"已处理V"标记）、输出位置（源文件夹内 `已处理\`）、成功/失败数量；**不能只写"输出目录"**；有失败则如实报告失败数量和原因（日志 `[失败]` 行）。
4. **继续任务询问**：询问是否继续时**必须再次列出编号与任务名称**：1 盖章 / 2 水印 / **3 盖章 + 水印**（4 是入口模式不是任务类型，不参与继续询问），或回复"结束"。

## 五、收尾规范（固定）

1. **收尾重启引导**：每项任务反馈完成后固定追加一句：
   > 本次任务已完成。下次继续工作时，直接对我说「**开始工作**」即可——我会先读取《偏好文件.json》，按你上次的任务类型和已确认的设置继续引导。
2. **主动总结**：每项任务完成时主动跑"本次经验总结"（任务类型与关键参数、用户新偏好、可复用经验、可改进点），**逐条问用户"哪些记入补充手册？"，用户确认的才写入** `补充手册.md`（见 references/workflows.md §补充手册）。
3. **工作过程文件**：任务 JSON、日志、临时脚本统一放 `运行组件\智能体调用\智能体调用工作过程文件\`，命名可辨识（`任务_类型_序号.json`、`日志_类型_序号.txt`、`临时_任务名\`）。

## 六、铁律（不得违反）

1. **公章尺寸不可压缩**（铁律）：章尺寸放不下时，用位置偏移（`textStamp.offset` / 盖章位置百分比）调整实现效果，绝不缩小公章；
2. **不许自创规则**：按文字盖章 = 写死规范（精确搜索匹配），不许改模糊匹配；参数含义以 task-spec.md 为准，不许发明新规则；
3. **不许跳过用户确认**：执行前必须复述方案并获用户确认；
4. **不许虚构成功结果**：按日志与退出码如实反馈，失败必须如实报告；
5. **输出永不覆盖源文件**：输出默认各源文件夹内 `已处理\`，文件名自动加 `已处理V` 递增；
6. **只扫根目录**：软件只处理各文件夹根目录的文件，不看子目录；`input` 仅支持文件夹目录（不支持单文件路径）。
7. **config.ini 只读不可改（铁律）**：读取全部参数经 `seal_info.py`（EXE --stamp-info 转 UTF-8）；禁止直接打开（GBK 乱码）、禁止修改。

## 七、用户扩展机制

- **补充手册.md**（`运行组件\智能体调用\` 下）：用户特有流程/长期偏好/成功经验，EXE 不会覆盖；每次加载本技能后必须同时读取（存在则读），**冲突时以补充手册为准**；写入前先备份 `.bak`、增量追加；
- **偏好文件.json**（同目录）：记录上次任务类型与已确认设置，用于「开始工作」重启流程；写入前先备份，只做增量修改。

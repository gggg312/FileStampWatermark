## 一、加载方式

1. 用户把 **文件批量盖章与水印工具软件文件夹** 指定给你的项目/工作目录。
   > **目录说明**：本手册与任务模板在 `运行组件\智能体调用\` 下（`智能体调用任务模板\` 是 4 个任务 JSON 模板）；《智能体用户使用说明.md》在软件根目录。
   >
   > **重要**：`运行组件\`（含本手册、`智能体调用任务模板\`、`印章库\` 等）都是**软件 EXE 首次运行后自动生成**的。如果用户给的文件夹里没有这些（用户还没运行过软件），请先让用户**运行一次 EXE**（双击打开、窗口正常显示后关闭），再重新加载文件夹。
2. 读取本手册（`运行组件\智能体调用\智能体调用手册.md`），然后按「技能包文件夹介绍与工作方式选择」判断技能包能否加载、向用户说明两种工作方式并请用户选择，再按「二、智能体工作流程指引」开始引导用户。
3. 执行完成后，按「六、结果反馈」向用户清晰报告结果。

### 技能包文件夹（file-stamp-watermark）介绍与工作方式选择

`运行组件\智能体调用\` 下除了本手册，还自动生成了一个**技能包文件夹** `file-stamp-watermark\`。它是本手册知识的"标准化封装"（同一套操作知识 + 4 个任务模板 + 3 个调用脚本），供支持"技能机制"的智能体平台（豆包、WorkBuddy 等）把本软件能力注册为正式技能。**用户不需要处理这个文件夹的任何内容**——选哪种工作方式由用户决定，你（智能体）负责说明区别并请用户选择。

#### 技能包结构

| 路径（在 `file-stamp-watermark\` 内） | 内容 | 用途 |
|---|---|---|
| `SKILL.md` | 技能入口：触发描述 + 操作流程 + 铁律 | 平台识别"何时使用本技能"并加载，正文与手册同源 |
| `references\task-spec.md` | 字段含义与默认值总表 | 与手册「五、字段说明」同源，按需读取 |
| `references\workflows.md` | 提问顺序、自定义任务流程、补充手册规则 | 与手册「二、第 3 步 / 自定义任务流程 / 十一」同源 |
| `references\boundary.md` | 软件能力边界与常见错误处理 | 与手册「三、软件功能边界 / 八」同源 |
| `assets\pdf-stamp.json` 等 4 个 JSON | 4 类任务的任务 JSON 模板 | 与手册「五、第一步」同一套模板 |
| `scripts\find_exe.py` | 定位软件主程序（EXE） | 封装手册「五、命令格式」的定位步骤 |

#### 两种工作方式（工作方式由用户选择，智能体不替用户决定）

**方式 A · 直接按调用手册工作（不加载技能包）**：智能体读完本手册，按手册里写好的步骤直接执行任务。不依赖任何安装、不依赖平台技能机制，任何智能体平台都能用。

**方式 B · 加载技能包后工作**：技能包把方式 A 的操作步骤封装成了现成脚本（定位软件、列出印章、执行任务），智能体按技能包调用更省事。需要当前平台能加载技能包（豆包把 `file-stamp-watermark` 文件夹放入用户技能目录 `.user_skills\`；WorkBuddy 放入 `C:\Users\<用户名>\.agents\skills\`，或在工作区内直接挂载技能包路径让智能体读取）。

**两种方式的区别（向用户说明用）**：A 和 B 能做的事完全一样，最终处理结果完全一致，都不影响软件功能。唯一的差别是：B 把执行步骤封装成了脚本，智能体调用时更省事；A 不依赖任何安装，任何环境都能用。

#### 工作方式选择流程（写入工作流程的第一步）

读完本手册后、开始引导用户前，按以下流程执行：

1. **判断技能包能否加载（含版本核对）**：
   - 当前平台是否支持技能机制（豆包 / WorkBuddy 等支持；不确定时按"不支持"处理）？技能包是否已安装或可直接加载（`file-stamp-watermark` 文件夹在技能目录 / 工作区可见）？
   - **核对技能包版本**：读技能包 `SKILL.md` 顶部「技能包版本」行（软件运行一次后自动注入，格式如 `技能包版本：1.0.0.31`），再运行软件 EXE `--version` 对比——**一致才可用**；不一致说明技能包是旧版，按"不可加载"处理。
2. **把判断结果如实告诉用户**：
   - **技能包可加载** → 展示两种方式及区别（见上），请用户选择：**A 直接按调用手册工作（不加载技能包）／ B 加载技能包后按技能包工作**；
   - **技能包不可加载（含版本不一致）** → 如实告诉用户"当前环境无法加载技能包（或技能包为旧版，需随软件更新），只能选 A（直接按调用手册工作）"，同时**告知技能包所在位置**：`运行组件\智能体调用\file-stamp-watermark\`（软件运行一次后自动生成，**每次运行软件都会按当前软件版本自动更新技能包版本号**）。说明用户可以自己想办法安装技能包——例如让智能体检查并调整该文件夹内容、按平台要求放入技能目录；若因版本不一致，**重新运行一次软件即可获得新版技能包**，装好后下次对话即可选 B；本次先按 A 继续。
3. **按用户选择执行**：用户选 A → 按本手册执行；用户选 B 且技能包可加载 → 加载技能包按 SKILL.md 工作流执行。
4. **继续引导**：确定工作方式后，立即按「二、智能体工作流程指引」继续引导用户完成本次任务，不再反复询问。

## 二、智能体工作流程指引

每次任务按下述流程逐步进行，**不要跳过任何一步**；信息不完整时先问清楚再执行，不要猜。

### 第 1 步：自检（初次加载本手册后执行一次）

对软件初始配置做自检，**不需要启动软件界面**，直接读取文件即可：

| 检查项 | 检查方法 | 未通过时处理 |
|---|---|---|
| 印章是否已导入 | 查看 `运行组件\印章库\` 目录，确认有印章图片文件（.png/.jpg） | 软件**默认不携带任何印章**。若本次任务是盖章/按文字盖章，必须先让用户在软件「印章参数」→「选择印章」中导入自己的公章后关闭软件、重新加载；只做水印任务可跳过 |
| 印章参数是否配置 | 运行 `EXE --stamp-info` 读取 config.ini 全部参数（含每章已保存的尺寸/不透明度/旋转/去白/渲染等），**把参数带入会话备用**（用户确认或调整参数时可直接引用，不必等工作时才去读） | 无印章图片时提示先导入印章；参数如需调整，提醒用户在软件界面「印章参数」中设置 |
| 手册/模板是否齐全 | 确认 `运行组件\智能体调用\` 下存在本手册与 `智能体调用任务模板\` 4 个 JSON | 说明用户未运行过 EXE，请其运行一次后再继续 |

> **注意：`运行组件\config.ini` 只能读、不能改（铁律）。** 该文件为 GBK 编码，直接读取会乱码；**必须通过 `EXE --stamp-info` 读取**（自动转 UTF-8 输出全部参数）。智能体可以读取全部参数以辅助工作，但**不得修改 config.ini**——软件配置由软件界面维护，改动会导致软件异常。
>
> **注意：软件默认不携带任何印章。** 需要盖章的任务开始前，请确认用户已在软件中导入自己的公章（`印章库\` 下有 .png/.jpg 文件）；只做水印任务则无需印章。

自检通过后，向用户简要确认："软件初始配置已就绪（目录结构齐全）"；若本次任务需要盖章，向用户说明当前印章及其已配置参数（尺寸/不透明度/旋转等，来自 `--stamp-info`），用户可指定覆盖或按当前值执行；有问题则列出缺项并请用户补充。

**读取印章与配置参数（`--stamp-info`）**：
- 命令：`"<EXE>" --stamp-info`，返回 UTF-8 JSON（只读不改 config.ini）；
- 返回内容：`tool`/`version`；`config` = config.ini 全部节与键值（原样）；`seals[]` = 印章清单（`name`/`path` + `params`：sizeMm/rotation/rotationHandle/opacity/randomParams/randomRange/randomOffsetXMm/randomOffsetYMm/removeWhite/tolerance/maxSplit/textureQuality/textureBrightness/textureBlob/textureGradient/textureWhite/textureSpot/textureRadial/textureCast/texturePresetIndex）；
- 用法：盖章/按文字盖章任务自检时必须调用一次，把 `seals` 参数带进会话；用户后续说"章大一点/小一点/透明一点"或指定数值时，对照已读参数确认修改项（对应 JSON 字段填覆盖值，不填则按该章已保存值执行）。

### 第 2 步：询问要做什么工作

让用户选择本次任务类型，**支持单选，也支持同时选多项**：

1. **盖章**（给 PDF 文件盖印章，可加骑缝章、按文字盖章）
2. **水印**（加文字水印——用户**不需要区分 PDF 水印还是图片水印**：用户只提供文件夹，智能体读取文件夹内容自动识别文件类型，自动选择对应水印方式；只有文件夹里同时有 PDF 和图片时才询问用户处理哪种）
3. **盖章 + 水印**（= 1 + 2 同时执行：按第 3 步分别收集盖章与水印信息，盖章先执行、水印后执行）
4. **对话定制任务**（不按预设流程，直接说出你的需求，智能体与你对话确认方案后执行——见下方「自定义任务流程」）

用户直接回复编号即可（如"1"或"3"）；也可用语言描述（如"两个都要"、"有个特殊需求，我们聊一下怎么做"），由智能体映射到对应选项。

### 第 3 步：收集任务信息（按选择的任务分别询问）

**盖章**（**固定提问形式：按下列 1-8 顺序逐项询问，不跳项、不合并、不自创问题**；每个问题都带默认值，用户可逐项指定；用户回复"其他默认/默认"即按默认值执行。读取源文件夹文件情况（有几个 PDF、文件名）后向用户说明）：

1. **源文件夹路径**（可一次给多个；软件只处理各文件夹**根目录**的 PDF，不看子目录）；
2. **盖哪个章**：让用户从印章库中选（或提供印章图片路径）；**该章的大小/不透明度/旋转使用软件中该章已配置的参数**，任务 JSON 不填 `sizeMm`/`opacity`/`rotation` 即按该章配置执行（填写才会覆盖用户界面设置）；
3. **盖哪些页**：**全部页（默认）/ 首页 / 尾页 / 自定义页码范围 / 按文字盖章**（在指定文字处定位盖章，如"公章"字样处）；
4. **盖章位置**：**居中（默认）**，或指定 X/Y 百分比位置；
5. **是否加骑缝章**：**不开启（默认）**；开启时必须向用户确认**骑缝章类型**：**全部页**（默认，每页都盖）/ **奇数页**（只盖 1、3、5…页）/ **偶数页**（只盖 2、4、6…页）；再确认位置：默认 **右**、位置 **50%**（1-100%），要其他值请用户指定：上 / 下 / 左 / 右（位置 1-100%）；单页 PDF 无需骑缝章；
6. **是否开启随机角度位移**：**不开启（默认）**；开启默认 旋转 **45°**、横向位移 **10mm**、纵向位移 **10mm**（用户可逐项指定修改）；
7. **是否开启盖章渲染**：**不开启（默认）**；开启默认 浓淡不均 / 径向压印 / 局部露白 / 内部斑点 **15**、斑点大小 **5**、渐变过渡 **10**、整体色偏 **0**（用户可逐项指定修改）；
8. **输出命名**：默认 `已处理V` + 数字递增（用户提要求才改，一般不询问）。

**水印**：

- 源文件夹路径（**可以一次给多个文件夹**；软件只处理各文件夹**根目录**的文件，不看子目录）；
- **智能体读取文件夹内容自动识别文件类型**，自动选择水印方式：
  - 文件夹里只有 PDF → 用 **PDF 水印**（模板 `pdf-watermark.json`）；
  - 文件夹里只有图片 → 用 **图片水印**（模板 `img-watermark.json`）；
  - **文件夹里既有 PDF 也有图片** → 询问用户：**1 只处理 PDF / 2 只处理图片 / 3 全部处理**；
  - 文件夹里既无 PDF 也无图片 → 提示用户该文件夹没有可处理的文件，请重新提供正确的文件夹；
- 水印文字内容。**支持多行**：用户可直接在对话中回车换行（推荐，所见即所得），或用 `\n` 表示换行。示范——用户这样输入：

  ```
  仅供：
  某某项目使用
  ```

  等效于 `仅供：\n某某项目使用`，程序按行分别渲染并自动按水印框宽度换行。若用户未说明换行方式，可用上述示例主动向用户确认；
- 水印样式：字体、字号、颜色、**透明度（默认 30%）**、**旋转角度（默认 30°）**、行距、字间距、对齐、位置（居中/底部/自定义）；
- 用户也可以选择"**由你（智能体）自行定义**"——此时使用上述默认值执行，并向用户说明默认值，用户不满意可要求调整。

### 自定义任务流程（第 2 步选 4 时）

不按上述固定提问逐项收集，改为与用户**对话推进**。开场白（固定，用户选 4 后立即发送）：

> 好的，我们不按固定流程来。请直接告诉我：**要处理哪些文件**（文件夹路径）、**你想做什么**（盖章/水印/其他特殊要求）。剩下的细节我会边问边跟你确认，比如盖哪些页、盖什么位置、水印什么样，最后把方案列给你确认后执行。

按下列顺序推进，**不跳步**：

1. **倾听需求**：问清——要做什么、处理哪些文件（文件夹路径，可多个）、期望的效果、有没有特殊约束；**复述一遍**与用户确认；
2. **拆解需求**：对照「三、能力清单」与「软件功能边界」，把需求拆成三类：①软件规则直接可实现 → 对应到任务 JSON 字段；②需要智能体判断 → 给出分析并翻译成软件可执行的规则；③超出软件范围 → 明确告知做不到，给出变通方案；
3. **提出方案**：列出将用哪个任务类型（盖章 / 水印 / 按文字盖章，可组合多个）、哪些用默认值、哪些需要用户指定，请用户确认；
4. **执行**：按「五、调用格式」读取模板或写 JSON（同类型多文件夹用 `input` 数组；盖章 + 水印组合生成对应任务逐个执行）；
5. **反馈**：按「六、结果反馈」规范报告；收尾按「七、8」告知下次重启方式。

### 第 4 步：确认后执行

1. 把收集到的信息复述给用户确认（任务类型、**全部源文件夹**、印章/水印参数、是否骑缝章等）；
2. 用户确认后，按「五、调用格式」读取对应任务模板、填入参数，**多个文件夹时每个文件夹生成一个任务 JSON，逐个执行**（每个文件夹各自输出到自己的 `已处理\` 子目录）；
3. 全部文件夹执行完成后，按「六、结果反馈」汇总报告结果与输出位置。

## 三、能力清单

| 任务类型 | 能力 | 必填参数 |
|---|---|---|
| `pdf-stamp` | 给文件夹内**所有 PDF 全部盖章**（可加骑缝章、可指定页范围） | 源文件夹、印章图片 |
| `pdf-watermark` | 给文件夹内所有 PDF **加文字水印** | 源文件夹、水印文字 |
| `pdf-text-stamp` | 按**指定文字**在 PDF 中定位盖章 | 源文件夹、印章图片、盖章文字 |
| `img-watermark` | 给图片文件夹内**所有图片加文字水印** | 源文件夹、水印文字 |

所有任务：**输出永不覆盖源文件**，输出默认在源文件夹内新建 `已处理/` 子目录，文件名自动加 `已处理V1、V2…` 递增，避免同名覆盖。**`input` 支持单个路径或数组**（同类型任务一个 JSON 处理多个文件夹，各输出到自身的 `已处理/`）。

> **水印自动选择**：用户只提供文件夹时，智能体按文件夹内容自动选择 `pdf-watermark`（只有 PDF）或 `img-watermark`（只有图片）；文件夹同时含 PDF 与图片时，询问用户三选一（1 只 PDF / 2 只图片 / 3 全部）。

### 软件功能边界（自定义任务时判断需求的关键依据）

**第 1 层 · 软件定位**：文件批量盖章与水印工具 = "PDF 盖章 + 文字水印"批量处理工具，通过命令行 JSON 调用。只做这两类操作，**不做**：PDF 内容编辑、图片处理（除文字水印）、格式转换、文档生成。

**第 2 层 · 4 类任务的精确规则（能做什么、怎么算）**：

- 盖章：范围（全部 / 首页 / 尾页 / 自定义页码）、位置（居中 / 百分比）、骑缝章（类型：全部页 / 奇数页 / 偶数页；位置：上 / 下 / 左 / 右、位置百分比、自动分割）、随机角度位移、盖章渲染——各参数含义与默认值见「五、字段说明」，这些就是**最终执行口径**，智能体不可发明新规则；
- **按文字盖章 = 写死规范**：按用户指定文字**精确搜索匹配**定位盖章，智能体**不可自行改变匹配逻辑**（如改成模糊匹配）；
- 水印：文字支持多行换行；字号按 `fsToS`（页面短边比例，**必须保留该字段**）；透明度/旋转默认值见「二、第 3 步」；
- 批处理：只扫各文件夹**根目录**（不看子目录）；`input` **仅支持文件夹目录**（单路径或数组，不支持单文件路径），数组=同类型一个 JSON；输出**永不覆盖源文件**，默认各源文件夹内 `已处理/`；**需要按文件粒度处理（部分文件跳过）时，用临时文件夹方案**（见「八、常见错误处理」末段）。

**第 3 层 · 软件做不到的（识别后变通，不硬跑）**：

| 用户需求 | 软件现实 | 智能体的处理 |
|---|---|---|
| "哪里该盖章、哪里不该盖章"（语义判断） | 只认 全部 / 首页 / 尾页 / 自定义 / 按文字 | **预设流程（1/2/3）**：拆成规则组合 + 建议，让用户确认；**对话定制（4）**：智能体可读取文件内容判断哪里该盖/不该盖，翻译成按文字盖章 + 关键词/偏移等可执行规则（见示范项目 2） |
| "盖在落款处/签字处"（智能定位） | 只认 居中 / 百分比 / 偏移 | 用「按文字盖章」（落款单位名）+ 偏移；文字不存在则建议尾页盖章 |
| 逐页不同章 / 不同位置 | 一次任务统一规则 | 拆成多个任务（每段页范围一个），或统一位置，让用户选 |
| 图片上盖图章 | **不支持**（图片只支持文字水印） | 明确告知做不到 |
| 合并 / 拆分 / 压缩 / 转格式 | 不支持 | 明确告知，不绕弯 |

**第 4 层 · 智能体职责边界**：

- **能**：理解需求、提出建议、把需求翻译成软件规则、组合 / 拆解任务、默认值兜底、写 JSON、执行、如实反馈；**对话定制（4）模式下读取文件内容做语义判断**（哪里该盖/不该盖、选关键词）并翻译成软件可执行规则；
- **不许**：改写死规则、让软件跑超出能力清单的操作、跳过用户确认、虚构成功结果、**压缩公章尺寸（铁律）**——章尺寸不可压缩时，用位置偏移（offset）等参数调整实现效果（见示范项目 2）。

**第 5 层 · 信息收集清单（自定义模式下问哪些）**：

- **必问**：需求描述、源文件目录（可多个）、处理对象（PDF / 图片 / 混合）、期望效果；
- **按需问**：印章 / 水印具体参数、特殊约束（页范围 / 位置 / 骑缝章等）、输出要求；
- **兜底**：用户说不清 → 用默认值并向用户说明，不满意再调。

**第 6 层 · 需求翻译示例（自然语言 → 规则组合的参照）**：

- 示例 1："只在合同落款单位处盖章" → 「按文字盖章」（落款单位名，如"西安某某公司"）+ 位置偏移；该文字在 PDF 中不存在 → 说明情况，建议改「尾页盖章」；
- 示例 2："每页不同位置盖章" → 一次任务做不到 → 拆成多个任务（每段页范围一个位置），或统一位置，让用户选；
- 示例 3："水印每页顶部和底部各一行" → 软件单框水印做不到 → 建议：一个框内多行文字（放中上部），或只做一个位置，让用户选；
- 示例 4："在合同落款处盖公章" → 关键词**不一定等于用户口头说的公司名**——合同正文里公司名常出现多次，直接用它做关键词会在所有位置盖章。应结合文档内容选能**唯一定位**的关键词（如「公司名（盖章）」仅命中签署页），并在方案中向用户说明（见示范项目 1）。

## 四、交互协议

执行任务前，必须向用户问清以下信息：

1. **任务类型**：盖章 / 水印 / **盖章 + 水印**（=1+2，可多选），或 **4 对话定制任务**（不按预设流程）。水印的 PDF/图片方式由智能体按文件夹内容自动识别（混合文件夹询问用户三选一）；按文字盖章是盖章任务内的一个选项。
2. **源文件夹路径**：要处理的文件夹（**可以一次给多个**——`input` 可为单个路径或数组；软件只扫描各文件夹根目录，不看子目录）。
3. 盖章任务：**印章图片路径**；是否加**骑缝章**（类型：全部页/奇数页/偶数页；位置：上/下/左/右）；盖哪些页（全部/首页/尾页/自定义/按文字）。
4. 水印任务：**水印文字**（可选：颜色、字号、透明度、旋转角度、位置）。
5. 按文字盖章：**要盖章的文字**（可选：盖章位置偏移）。
6. 输出偏好：文件命名方式（默认 `已处理V` + 数字递增）。

**规则**：

- 源文件夹路径由**软件自行校验**（路径不存在时软件返回明确错误）；
- **预设流程（1/2/3）**：智能体只读取源文件夹**目录**（识别文件类型以选择水印方式），**不读取文件内容**；
- **对话定制（4）**：智能体**可以读取文件内容**做判断（哪里该盖/不该盖、选关键词），并把判断翻译成软件可执行规则——软件仍是执行通道，见「三、软件功能边界」与「十、示范项目」；
- 多个文件夹时，一次列出全部路径让用户确认后再逐个执行；
- 印章图片必须存在（路径错误时软件会报错，请如实向用户反馈）；
- 信息不全时**先问清楚再执行**，不要猜。

## 五、调用格式

### 第一步：读取任务模板（不要从零写 JSON）

软件启动后会在 `运行组件\智能体调用\智能体调用任务模板\` 下自动生成 **4 个任务 JSON 模板**：

| 模板文件 | 任务类型 |
|---|---|
| `pdf-stamp.json` | PDF 全部盖章 |
| `pdf-watermark.json` | PDF 加水印 |
| `pdf-text-stamp.json` | 按文字盖章 |
| `img-watermark.json` | 图片水印 |

智能体按用户确认的任务类型与**水印识别结果**读取对应模板文件，只替换其中的动态值：

- `input`：改为用户提供的源文件夹路径（**可为单个路径或数组：数组=同类型任务一次处理多个文件夹，各输出到自身 `已处理\`；同一类型任务不要拆成多个 JSON**）
- 盖章任务：`stamp.image` 改为用户印章图片路径
- 水印任务：**文件夹只有 PDF → 用 `pdf-watermark.json`；只有图片 → 用 `img-watermark.json`**；`watermark.text` 改为用户水印文字
- 其他字段按用户要求调整（未提及时保持模板默认值；智能体与用户约定"自行定义"时使用手册「二、工作流程指引」中的默认值）

替换后**另存为新的 JSON 文件**（不要覆盖模板本身），再执行命令。

> **模板仅为首次调用的起点，不是强制格式。** 智能体可自由修改模板字段、增删内容，或从零编写 JSON——软件按**最小必要字段**校验：`task`、`input` 及对应任务关键参数（盖章 `stamp.image`、水印 `watermark.text`、按文字盖章 `textStamp.keyword`）必填，其余字段均有默认值，能跑通即可。

### 任务 JSON 复用工作流（固定规范）

1. **首次任务**：读取对应模板 → 填入参数 → **另存为新 JSON**（如 `任务_stamp_1.json`）→ 执行 → **成功后保留该文件**；
2. **后续同类型任务**：**优先复制上次成功的 JSON**，只修改变化的参数（典型只改 `input` 文件夹路径、或用户新指定的水印文字/印章/开关），**其他已验证字段保持不变**——不要每次从模板全量重写；
3. **回到模板的情况**：任务类型不同（盖章→水印→按文字盖章）、或软件升级后本手册字段说明有变化时，重新对照模板；
4. **同类型多文件夹**：把 `input` 改为数组即可（一个 JSON 处理多个文件夹），不要按文件夹拆多个 JSON。

### 命令格式

```
"<软件文件夹>\<EXE文件名>.exe" --batch "<任务.json路径>" --log "<日志路径>"
```

> **工作过程文件存放**：任务 JSON 与执行日志**统一放 `运行组件\智能体调用\智能体调用工作过程文件\` 子目录**（不存在则创建，EXE 不会覆盖/清理它；`--log` 路径可直接写该目录下），**不要散落在软件根目录/EXE 同目录**（见「七、10」）。

> **识别软件主程序（EXE）——不要依赖完整文件名**（文件名带版本号，每次发版都会变）：
>
> 1. **首选**：软件文件夹**根目录下唯一的 .exe** 就是主程序（运行组件内只有 .dll，没有 .exe；运行组件由 EXE 首次运行后生成——若目录下没有运行组件或本手册，说明用户还没运行过软件，先让用户运行一次）。
> 2. **验证（推荐）**：运行 `"<该EXE>" --version`，输出包含 `文件批量盖章与水印工具` 即为正确程序（输出示例：`文件批量盖章与水印工具 1.0.0.1`）。
> 3. **辅助线索**：文件名以 `文件批量盖章与水印工具` 开头（后接版本号），版本号部分忽略。
> 4. **多个 EXE 并存**：用户目录可能保留多个历史版本 EXE。此时对根目录下**所有** `文件批量盖章与水印工具*.exe` 逐个运行 `--version`，选择输出包含 `文件批量盖章与水印工具` 且**版本号最大**的那个作为主程序（版本号形如 `X.Y.Z.W`，按数字逐段比较，不要按字符串排序，也不要只取文件名）。

### 必改字段清单（不改的后果）

| 任务类型 | 必改字段 | 不改的后果 |
|---|---|---|
| `pdf-stamp` | `input`、`stamp.image` | 印章路径是占位 → 报错"印章图片不存在"，退出码 1 |
| `pdf-watermark` | `input`、`watermark.text` | 水印文字按默认"内部资料"输出，可能不符合用户要求 |
| `pdf-text-stamp` | `input`、`stamp.image`、`textStamp.keyword` | 印章路径是占位 → 报错；关键词不改 → 找不到文字、输出 0 个章但仍显示成功 |
| `img-watermark` | `input`、`watermark.text` | 水印文字按默认"内部资料"输出，可能不符合用户要求 |

> 模板顶层带 `_说明` 字段（软件解析时自动忽略，不影响执行），每次调用前按 `_说明` 核对必改项，可避免绝大多数可预期的失败。

### 字段说明（模板中出现的全部字段）

**stamp（印章）**

- `image`：印章图片绝对路径（必填）。
- `sizeMm`：印章边长（毫米）。**不填时按软件中该章已配置的参数**；填写才覆盖（避免模板默认值覆盖用户界面设置）。
- `rotation`：旋转角度。不填时按该章已配置参数；填写才覆盖。
- `opacity`：不透明度 0-100。不填时按该章已配置参数；填写才覆盖。
- `randomParams`：是否开启**随机角度位移**（false/true，默认 false）。
- `randomRotation`：开启时随机旋转角度范围（默认 45）。
- `randomOffsetXMm`/`randomOffsetYMm`：开启时随机横向/纵向位移范围（mm，默认 10/10）。
- `textureQuality`：是否开启**盖章渲染**（false/true，默认 false）。
- `textureBrightness`/`textureRadial`/`textureWhite`/`textureSpot`：浓淡不均/径向压印/局部露白/内部斑点上限（开启时默认 15）。
- `textureBlob`：斑点大小上限（默认 5）。
- `textureGradient`：渐变过渡上限（默认 10）。
- `textureCast`：整体色偏上限（默认 0）。
- `texturePresetIndex`：渲染方案（0 自定义，1-4 方案N）。
- `seam.enabled`：是否加骑缝章（false=不加；true=加，类型见下）。
- `seam.type`：`全部页`（每页都盖，默认）/`奇数页`（只盖 1、3、5…页）/`偶数页`（只盖 2、4、6…页）。
- `seam.pos`：`上`/`下`/`左`/`右`（默认 右）。
- `seam.percent`：骑缝章位置百分比（默认 50）。
- `seam.split`：`auto`（自动按页数）或数字。

**range（盖章范围，pdf-stamp）**

- `mode`：`all` 所有页 / `first` 首页 / `last` 尾页 / `custom` 自定义（配 `start`/`end`：`start`=起始页码、`end`=结束页码，含两端；页码按文件实际页序 1 起）。
- `xPct`/`yPct`：盖章位置（页面百分比中心，默认 50/50）。

**watermark（水印）**

- `text`：水印文字（必填）。
- `fontName`：字体（默认微软雅黑）。
- `colorArgb`：颜色 ARGB 整数（默认 -2147476961 = 深蓝）。
- `opacity`：透明度 0-100（默认 30）。
- `rotation`：旋转角度（默认 30）。
- `align`：对齐 0 左 / 1 中 / 2 右。
- `letterSpacing`/`lineSpacing`：字距/行距（-150~300）。
- `fontScale`：字号与框高比例（默认 0.8）。
- `fsToS`：**字号/页面短边比例**（默认 0.08，即字号≈页面短边 8%，横竖页/横竖图片字号一致）。**必须保留此字段**——缺省时旧版按"框高×fontScale"计算会得到约为页面高 48% 的特大字号，水印将超出页面。
- `pos`：位置 `center`（居中）/ `bottom`（底部）/ 或用 `x`/`y`/`w`/`h` 直接指定相对位置（0~1）。

**textStamp（按文字盖章）**

- `keyword`：要盖章的文字（必填）。
- `ctxRange`：上下文检索范围（默认 10）。
- `matchMode`：`all` 全部命中 / `any` 任一命中。
- `offset.x/y`：盖章位置偏移（毫米）。
- `ignoreSpace`：搜索关键词时是否忽略空格/空白（false=不忽略，按原文精确匹配；true=忽略空白后再匹配）。

**output（输出）**

- `dpi`：输出清晰度（PDF 默认 150）。
- `mark`：文件名标记（默认 `已处理V`，编号直接接在后面）。
- `pos`：标记位置 0 文件名后 / 1 文件名前。
- `seq`：编号类型 0 数字 / 1 大写字母 / 2 小写字母。
- `pad`：编号位数 1/2/3。
- `ts`：是否插入时间戳（false/true）。
- `tsFormat`：时间戳格式（.NET 日期格式，默认 `yyyyMMdd`，如 `yyyyMMdd_HHmm`）。
- `dir`：自定义输出目录（缺省=源文件夹`已处理`）。

## 六、结果反馈

软件执行完成后：

1. **退出码**：
   - `0` = 全部成功
   - `1` = 参数或路径错误（任务未执行）
   - `2` = 部分文件失败（明细见日志）
2. **日志文件**：命令中 `--log` 指定的路径（缺省 `运行组件\batch.log`）。日志末尾 `===== 给用户的反馈 =====` 段落可直接向用户转述。
3. **向用户报告**（示例）：

   > 已完成 3 个 PDF 的盖章；输出文件：批量放置印章1_已处理V1.pdf、方格带横向页面_已处理V1.pdf、测试组A_已处理V1.pdf（位于 D:\投标文件\已处理，源文件未改动）。失败 0 个。

   **反馈必须包含每个输出文件的实际文件名**（含"已处理V"标记；日志 `[生成]` 行与 `===== 给用户的反馈 =====` 段均会列出），不能只写"输出目录"；若有失败：如实报告失败数量和原因（见日志 `[失败]` 行）。
4. **继续任务询问**：一项任务完成后，如需询问用户"是否继续下一项任务"，**必须再次列出编号与任务名称**：1 盖章 / 2 水印 / **3 盖章 + 水印**，或回复"结束"让智能体汇总本次结果，**不要只写编号、不要漏掉 3**。

## 七、智能体工作规范（固定规范，不得随意变更）

1. **固定提问形式**：盖章/水印任务按「二、第 3 步」列出的固定顺序逐项询问，**不跳项、不合并、不自创问题**；每个问题都带默认值，用户可逐项指定；用户回复"默认/其他默认"即按默认值执行。
2. **任务选项编号**：任务询问必须提供完整编号：**1 盖章 / 2 水印 / 3 盖章 + 水印 / 4 对话定制任务**；继续任务询问提供 **1 盖章 / 2 水印 / 3 盖章 + 水印** + "结束"（**4 是入口模式不是任务类型，不参与继续询问**）；编号必须带任务名称，不只写编号。
3. **反馈规范**：任务完成后反馈**必须包含实际输出文件名**（含"已处理V"标记）与输出位置；成功/失败数量如实报告。
4. **JSON 复用**：同类型任务优先复用上次成功 JSON，只改差异参数（见「五、任务 JSON 复用工作流」）；任务类型变化或字段说明变化时回到模板。
5. **文件夹识别**：处理前读取源文件夹内容——识别文件类型选择水印方式；文件夹无 PDF/图片、或疑似输出目录（已处理）时，提醒用户并提供正确路径，**不要空跑任务**。
6. **多文件夹**：同类型多文件夹用 `input` 数组（一个 JSON），逐个执行、逐个反馈，各输出到自己 `已处理\`。
7. **对话定制任务**：选 4 时按「自定义任务流程」推进，最终仍落到任务 JSON 执行；把需求翻译成规则必须对照「软件功能边界」——**不许自创规则、不许让软件跑超出能力清单的操作、不许跳过用户确认、不许虚构成功结果**。
8. **收尾重启引导**：每项任务反馈完成后，固定追加一句：

   > 本次任务已完成。下次继续工作时，直接对我说「**开始工作**」即可——我会先读取《偏好文件.json》，按你上次的任务类型和已确认的设置继续引导，无需重新交代全部信息。

9. **主动总结**：每项任务完成收尾时，主动跑一遍"本次经验总结"——①任务类型与关键参数；②用户新表达的偏好/约束；③可复用的成功经验；④下次可改进点。逐条向用户确认"**以下哪些记入补充手册？**"，用户确认的条目才写入 `补充手册.md`（见「十一、补充手册」），不确认不写。
10. **工作过程文件统一存放**：智能体产生的所有工作过程文件——任务 JSON、执行日志、临时脚本、临时文件夹——**统一放在 `运行组件\智能体调用\智能体调用工作过程文件\` 子目录**（不存在则创建；EXE 不会覆盖/清理该目录，与补充手册/偏好文件同属智能体数据），**不要散落在软件根目录/EXE 同目录**。命名保持可辨识：任务 JSON 如 `任务_类型_序号.json`、日志如 `日志_类型_序号.txt`、临时文件夹如 `临时_任务名\`。任务 JSON 复用工作流要求保留成功 JSON 供下次复制，放此目录便于统一管理。

## 八、常见错误处理

| 现象（日志内容） | 含义 | 处理 |
|---|---|---|
| `任务文件不存在` | JSON 路径写错 | 检查 JSON 路径 |
| `任务 JSON 解析失败` | JSON 格式错误 | 检查引号/逗号/编码（必须 UTF-8） |
| `缺少 task 或 input` | 字段缺失 | 补全 `task`/`input` |
| `输入目录不存在` | 源文件夹路径错误 | 向用户核实路径 |
| `印章图片不存在` | 印章路径错误 | 向用户核实印章路径 |
| `缺少 watermark.text` | 水印任务缺文字 | 向用户要水印文字 |
| `批处理超时` | 文件过多处理超 10 分钟 | 告知用户分批处理 |
| `加密或无法打开` | 个别 PDF 加密/损坏 | 报告该文件，其余已处理 |
| 文件夹里没有 PDF 或图片 | 智能体识别源文件夹无支持文件 | 提示用户该文件夹没有可处理的文件，并提醒检查是否给成了「已处理」等输出目录/空文件夹，请提供正确的源文件夹 |
| 退出码 2 | 部分失败 | 读日志 `[失败]` 行，向用户说明 |

> **按文件粒度处理（部分文件跳过/单独处理）**：`input` 仅支持文件夹目录、不支持单文件路径。需要只处理部分文件时，用**临时文件夹方案**：①把要处理的文件复制到临时文件夹（放 `运行组件\智能体调用\智能体调用工作过程文件\临时_任务名\`，不要建在源文件夹内）；②对临时文件夹执行任务，输出到 `临时\已处理\`；③把输出文件**移回源文件夹的 `已处理\`**；④删除临时文件夹。源文件夹不受污染（软件只扫根目录）。

## 九、偏好文件规则

`偏好文件.json`（与手册同目录，即 `运行组件\智能体调用\` 下）记录用户**运行态短期偏好**，**只允许智能体读写，软件永不读取**（软件使用自己的配置，互不干扰）。**长期扩展规范**（用户特有流程、成功项目经验）请用「十一、补充手册」——偏好文件记录"上次做了什么"，补充手册记录"以后怎么做"。

- 智能体写入前**先备份**（复制一份 `偏好文件.json.bak`）。
- 只做**增量修改**（改用户需要的字段），不要整体重写。
- 文件损坏时，可删除后由软件重新生成默认配置（或告知用户重新填写）。
- 建议记录内容：用户常用印章路径、常用水印文字、输出命名偏好、是否常加骑缝章、**上次任务类型与已确认的自定义方案**等。
- **「开始工作」重启流程**：收到用户说"开始工作 / 继续工作"时，先读取本文件——有上次记录 → 向用户复述"上次做的是 X（设置是……），本次是继续、还是换新任务？"，按用户回答继续；无记录 → 按「二、第 2 步」正常询问。

## 十、示范项目（可复用的完整工作样例）

> 以下两个样例来自真实项目（按文字盖章 / 对话定制任务），展示"需求 → 方案 → 执行 → 验证"的完整闭环。遇到相似需求可直接参照，不必从零摸索。

### 示范 1：按文字盖章——关键词要能唯一定位（避免全文多处命中乱盖）

- **需求**：给合同签署页甲方盖章处盖公章。
- **难点**：合同正文里公司名出现多次（正文、开票信息、签署页等），直接用公司名做关键词会在所有命中处盖章（乱盖）。
- **做法**：
  1. 读取 PDF 文本，找出「公司名（盖章）」这种**签署页专属**写法——全文仅命中签署页 1 处；
  2. 用 `pdf-text-stamp` 任务，`textStamp.keyword` = 「公司名（盖章）」，`matchMode` 保持 `all`（此时全文仅 1 处，安全）；
  3. 执行后按「六、结果反馈」报告，并在方案中向用户说明关键词选取理由。
- **要点**：关键词不等于用户口头说的公司名；先读内容确认唯一性，再执行。

### 示范 2：章必须压甲方名、不压乙方名——几何约束 + 移动章中心（对话定制任务）

- **需求**：合同签署页盖公章，**必须压住甲方公司名，绝不能压到乙方公司名**；公章尺寸不可压缩（铁律）。
- **难点**：签署页甲方、乙方两行文字垂直间距仅 **16.5mm**，而公章直径 **44mm**——按默认落章（章中心=文字中心）必然同时压到乙方。
- **做法**：
  1. **读取内容 + 测量**：定位签署页两行文字坐标（PDF 坐标），甲方行 y≈681、乙方行 y≈634（间距 46.8pt≈16.5mm），章半径 62.4pt；
  2. **识别几何约束**：章直径 > 两行间距 → 默认落章位置不可行；
  3. **铁律不缩章**：不缩小公章（44mm），改用 **offset 移动章中心**——章中心对准甲方名称（左移 6.3mm），并上移到章下缘高于乙方文字上沿（上移 8.8mm），留约 1mm 安全余量；
  4. **执行**：`pdf-text-stamp` 任务，关键词用「公司名（盖章）」（仅签署页 1 处），`textStamp.offset = {"x": -6.3, "y": -8.8}`，**不填 `sizeMm`**（保持 44mm）；
  5. **闭环验证**：输出后解析章图绘制位置/渲染页面像素，确认章中心实测位置、章直径未变（≈44mm）、章覆盖甲方名称 ≥ 一半、乙方上方有余量——不符则微调 offset 重跑，验证通过才交付。
- **要点**：布局几何限制优先于"默认落章位置"；尺寸不可改时，位置偏移（offset）是正确出路；**每次输出都要验证位置再交付**。

## 十一、补充手册（用户扩展，推荐维护）

**官方手册每次运行 EXE 会自动重置为出厂内容**（本文件与任务模板都是出厂配置）。你的智能体若要长期记住"你的习惯"和"你们的成功经验"，请维护同目录 **`补充手册.md`**——它是独立用户文件，**EXE 不会覆盖它**（与 `偏好文件.json` 相同，软件只覆盖出厂手册与模板）。

**作用**：让智能体越用越懂你——用户特有流程、常用默认值、成功项目经验、注意事项，都沉淀在这里，下次同类任务直接复用。

**加载规则（智能体必须遵守）**：

- 每次加载官方手册后，**必须同时读取 `补充手册.md`**（存在则读，不存在跳过）；
- **冲突时以补充手册为准**（用户扩展优先于出厂默认）。

**写入规则（智能体必须遵守）**：

- 任务过程中**主动发现**可沉淀内容：用户表达的长期偏好/约束（如"以后都这样"、"我们公司的章要压住甲方名"）、本次成功方案、特殊处理；
- **每项任务完成收尾时，主动跑一遍"本次经验总结"**（见「七、9」）：①任务类型与关键参数；②用户新表达的偏好/约束；③可复用的成功经验；④下次可改进点；
- 把总结**逐条展示给用户确认**："以下哪些记入补充手册？"——**用户确认的条目才写入**，不确认不写；
- 写入时**增量追加、不改旧条目**；写前先备份一份 `补充手册.md.bak`；
- 文件损坏时删除后可由用户/智能体重建（软件不生成也不依赖它）。

**建议记录内容示例**：

- 用户特有流程："合同盖章统一压住甲方公司名，章不压乙方"；
- 常用默认值："水印默认 30% 透明度、旋转 30° 不用再问"；
- 成功项目经验："某类文件盖章 = 用「公司名（盖章）」关键词 + 偏移 (x, y)，下次同类直接复用"。
